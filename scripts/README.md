# Scripts

## Regenerate the Garmin profile

The runtime library has no dependencies. Profile generation uses `openpyxl` from
the development dependency group:

```sh
uv sync --locked --dev
curl -fL https://github.com/garmin/fit-sdk-tools/releases/download/21.217.0/Profile.xlsx -o scripts/data/Profile.xlsx
uv run python scripts/parse_profile.py scripts/data/Profile.xlsx --version 21.217.0
uv run python scripts/parse_profile.py scripts/data/Profile.xlsx --version 21.217.0 --check
```

The workbook does not contain a release version; pass the version of the pinned
release you downloaded. `fittie/profile/source.json` records its URL, SHA-256,
version, and definition counts. Verify the download against the checked-in hash
when reproducing an existing release. `--check` compares every generated byte,
including the source hash, and exits nonzero without writing if anything differs.

The script generates `messages.py`, `fit_types.py`, `mesg_nums.py`, `version.py`,
and `source.json`. Output defaults to this repository regardless of the working
directory; `--output-root` supports an isolated checkout or scratch directory.
It never imports existing generated definitions. All parsing, reference resolution,
component dependency validation, and Python compilation finish before any output
is replaced. Each changed file is replaced atomically. Output contains no timestamp
and does not depend on an external formatter.

The parser reads both workbook sheets directly, resolves references within each
message using that workbook's enum values, retains subfield accumulation, handles
decimal scales and arrays, and preserves deprecated enum aliases for reference
resolution. The last enum alias is the displayed name, matching Garmin's Python
SDK. It rejects unresolved references, unknown types/targets, duplicate definitions,
invalid metadata, formulas, and dependency cycles. The SDK's fieldless `pad`
definition is generated from its `mesg_num` entry because Messages omits it.

For an independent metadata check against the matching Garmin SDK:

```sh
uv run --with garmin-fit-sdk==21.217.0 python scripts/compare_profile.py
```

The SDK is only an optional verification dependency. The comparison covers all
messages, fields, enums, base types, scales, offsets, arrays, units, component
mappings, accumulated targets, and subfield references. For 21.217.0, it reports
three documented upstream differences: the workbook retains unused `avg_vam`
bit widths in session/lap, and its named `weight` type is `uint16` in the SDK.
Unexpected differences fail the check. Neither these checks nor profile coverage
imply full FIT feature completeness.

Run `uv run pytest` for self-contained generator and decoder regression tests.
The Python 3.14 CI job also downloads the pinned workbook, verifies its hash,
checks regeneration, compares metadata, and runs an encoder/decoder interoperability
check with Garmin's matching SDK.

## Performance and sample verification

`scripts/benchmark_decode.py` measures full decoding with synthetic workloads and
optional FIT samples. `scripts/compare_components.py` compares numeric component
values with an optional installed Garmin SDK. See the component documentation for
methodology and recorded results.

## Compile README

`scripts/compile_readme.py` updates the marked sections of the main README from
nested README files. This is a development command, not part of the runtime API.


## Full SDK interoperability

```sh
uv run --with garmin-fit-sdk==21.217.0 python scripts/compare_sdk.py
uv run --with garmin-fit-sdk==21.217.0 python scripts/compare_sdk.py --samples tests/data/from_garmin_sdk
```

The first command generates a reproducible sample with Garmin's encoder and checks
Fittie's decoding and encoding against Garmin, without relying on ignored FIT
binaries. CI runs it on Python 3.14. The second adds any local SDK samples, comparing
all returned native/developer values with the original input as decoded by Garmin,
and checking full Fittie round trips. HR merging and enum/date conversion are enabled.
